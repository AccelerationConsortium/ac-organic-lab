# Coordinated custody release — 2026-09-08

This release integrates the existing custody, authorization, inventory, and UI
work with the agreed product direction. It does not implement the entire ELN,
LIMS, or inventory migration roadmap.

## Changes and boundaries

- Bitácora keeps OpenRouter, direct editing, manual steps, inventory access,
  scientific drafts, and review. Agent-proposed physical facts require a human
  confirmation. Missing record IDs and ambiguous writes remain uncertain.
- Run authorization requires a project PI or lab admin, including CI exceptions.
  Any authenticated caller can revoke. Preview is not authorization.
- BitacoraDB contract 0.15.1 adds scoped idempotent custody writes, expected
  location checks, and registered Plan references. Its additive migration must
  precede deployment of the updated clients.
- The lab connector verifies launcher identity, opens the required Plan before
  live execution, and retries only replay-safe ledger requests. It does not
  automatically repeat uncertain physical actions.
- The dashboard remains an operational assistant. Existing saved planning
  sessions are preserved; a second scientific planning lifecycle is superseded.

## Validation and remaining scope

The integrated Python suites, dashboard frontend suite (258 tests), Bitácora
browser suite (13 tests), TypeScript check, both production builds, and the
complete Alembic migration chain were checked in isolated environments. Hardware
execution was not used as a deployment test.

Full incremental execution recovery and a durable filing outbox remain future
work: opening a Plan does not guarantee every in-flight step survives a process
crash. Inventory still has its existing single writer; migration to the record
layer is not included. Standalone installation still needs dependency packaging.
These limitations must not be described as completed product capabilities.

Older worktrees were compared with the integrated branches. Their snapshots are
preserved in the host's release-review-20260908 and worktree-cleanup-backups
folders; stale code should not be merged over the newer safety fixes.
